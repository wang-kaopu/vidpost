# 账号在线状态检测

## 适用范围

抖音、Bilibili、百家号和搜狐使用平台用户接口检测账号在线状态，不再为 `ping` 创建 Playwright browser/context。

账号登录本身仍在 Electron Webview 中由平台官网完成。登录后的 `syncNickname()` 也保持原流程；本文只描述账号管理页面触发的 `ping`。

## 输入与请求身份

检测器读取 `~/.agenthunt/cookie_files/<accountId>_<platform>.json`。文件必须是包含 `cookies` 数组的 Playwright storage-state JSON；文件缺失、JSON 损坏或没有目标域有效 Cookie时直接报检测异常，不把账号标记为离线。

Cookie 只保留未过期记录，各平台域范围如下：

| 平台 | Cookie 域 |
| --- | --- |
| 抖音 | `douyin.com` 及子域 |
| Bilibili | `bilibili.com` 及子域 |
| 百家号 | `baidu.com` 及子域 |
| 搜狐 | `sohu.com` 及子域 |

请求 User-Agent 从 `assets/douyin/browser-identity.windows.json` 或 `assets/douyin/browser-identity.macos.json` 读取，必须与宿主系统匹配并包含 Chrome 138。账号检测不创建自定义指纹环境，也不使用登录窗口中的 Chrome 148 常量。

搜狐还要求账号文件包含 `https://mp.sohu.com` 的完整 localStorage。检测器从 `vuex.app.userInfo.id` 读取平台 `accountId`，从 `<userCode>-sp-cm`、`preview-sp-cm` 或 `mp-cv` 读取 `sp-cm`，并读取 `preview-dv-id`。任一必需字段缺失时直接报检测异常。

## 平台请求

### 抖音

```http
GET https://creator.douyin.com/web/api/media/user/info/?msToken=<msToken>&a_bogus=
Cookie: <douyin cookies>
User-Agent: <host Chrome 138 UA>
```

`msToken` 取账号文件目标域有效 Cookie 中最后一个同名值；Cookie 快照不存在该字段时按原包行为传空字符串，不读取 LocalStorage `xmst` 代替。响应存在对象类型的 `user` 时在线，昵称读取 `user.nickname`。

### Bilibili

```http
GET https://api.bilibili.com/x/web-interface/nav
Cookie: <bilibili cookies>
User-Agent: <host Chrome 138 UA>
```

`data.isLogin === true` 时在线，昵称优先读取 `data.name`，其次读取 `data.uname`。`data.isLogin === false` 时明确离线。

### 百家号

```http
GET https://baijiahao.baidu.com/builder/app/appinfo
Cookie: <baidu cookies>
User-Agent: <host Chrome 138 UA>
```

响应存在对象类型的 `data.user` 时在线，昵称读取 `data.user.name`。

### 搜狐

```http
GET https://mp.sohu.com/mpbp/bp/account/check/user?accountId=<accountId>
Cookie: <sohu cookies>
User-Agent: <host Chrome 138 UA>
Referer: https://mp.sohu.com/mpfe/v4/contentManagement/news/addvideo
dv-id: <preview-dv-id>
sp-cm: <sp-cm>
mp-cv: <mp-cv，可选>
```

响应 `code === 2000000` 时在线。搜狐鉴权接口没有经过验证的稳定昵称字段，因此 `ping` 不更新昵称。

## 重试、超时和错误语义

每个平台收到可解析但未匹配在线标志的响应后立即再次请求，最多请求 3 次，不设置重试间隔。Axios 抛出传输异常时不会进入下一次循环。

单账号检测通过 `Promise.race()` 限制为 20 秒。超时只结束上层等待，不向 Axios 传递 `AbortSignal`，因此不会主动取消已经发出的底层请求。

状态分类如下：

| 结果 | 行为 |
| --- | --- |
| 匹配平台在线标志 | 更新远程状态为 `online`，有昵称时同时更新昵称 |
| HTTP `401/403` | 更新远程状态为 `offline` |
| 3 次响应均未匹配在线标志 | 更新远程状态为 `offline` |
| 网络错误、超时、其他 `4xx`、`429`、`5xx` | 抛出检测异常，远程账号状态和昵称保持不变 |

## 批量检测

“检测本页账号”只处理当前分页中的账号，包含搜狐账号。队列每批最多并发 3 个账号，等待当前批全部 settled 后再启动下一批，单个账号异常不会中断其他账号。

整批任务通过 `Promise.race()` 设置 5 分钟兜底。超时后不再启动新批次，但不主动取消已经开始的账号检测。页面在批量流程结束后只刷新一次账号列表，并汇总显示成功更新、检测异常和未完成数量；明确检测为离线属于成功更新，不计入异常。

## 废弃实现

以下三类探活方式已经删除，不提供兼容或兜底：

- 打开平台创作后台页面检测最终 URL。
- 搜索页面标题或 HTML 中的“创作中心”“扫码登录”等文案。
- 根据页面 DOM 是否出现登录后元素判断 Cookie 有效性。
