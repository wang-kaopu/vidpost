# 发布窗口架构

## 模块与构建

Electron 主进程、平台实现、服务层和开发脚本统一使用 TypeScript + ESM。`npm run build:electron` 通过 esbuild 生成 `.build/main.js`；sandbox preload 源码为 `preload.ts`，运行产物为 `.build/preload.cjs`。

仓库使用 npm workspace，正式前端位于 `app/App.vue`，`app/src` 保留为后端联调 Demo。

## 当前发布宿主

四个平台发布流程使用 Electron 托管的账号发布窗口作为浏览器宿主。Playwright 不再在发布路径中调用 `chromium.launch()`、`browser.newContext()` 或 `context.newPage()` 创建发布页面，而是通过 Electron 启动时暴露的本地 CDP 端口接管已有发布窗口。

`ping`、昵称同步和发布状态查询暂不迁移，仍继续使用原有 Playwright browser/context 流程。

## 窗口与队列

发布窗口按全局唯一 `accountId` 复用。每个账号对应一个 Electron persist partition，partition 由 `resolvePartitionForAccount()` 解析。

同一个 `accountId` 的发布任务串行执行；不同账号可以并行执行。某个账号的任务失败后，该账号队列暂停，避免后续任务覆盖失败现场。

## 窗口显示规则

发布窗口按需创建。当前发布过程会 `show()` 并 `focus()` 发布窗口，便于观察自动化执行现场。正常发布成功后会保存 cookie、回到账号 marker 空白页并隐藏。

发布失败、超时或平台返回非成功结果时，窗口保持显示并保留异常发生时的平台页面，方便人工排查。用户关闭已展示窗口时只隐藏窗口，不销毁账号窗口。

## 账号状态

`accountFile` 仍是优先状态来源。有 `accountFile` 时，发布开始前只把其中的 cookies 注入账号 partition；不注入 localStorage。没有 `accountFile` 时，直接使用账号 partition 中已有状态。

发布成功后，如果存在 `accountFile`，只导出当前 partition cookies 回写文件，`origins/localStorage` 写为空数组。旧的 publish 路径中依赖 Playwright `storageState()` 注入和导出完整 storage state 的方式已废弃。
